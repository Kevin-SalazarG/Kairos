# Kairos RX

Personal capture build for a Radeon RX 6600 (8 GB), Ryzen 5 5600G, 16 GB RAM and a 1080p display. Built on Kairos / libobs 32.2.2.

## Profile

In Quality, select the **Balanced / QP16** profile, then **Apply**. It uses AMD HEVC texture encoding at 1920×1080 and 60 FPS, native CQP 16, Balanced speed, pre-analysis disabled, a 120-second replay and a 1024 MiB encoded-packet budget. Audio devices, microphone levels, hotkeys, voice phrases and the output folder are preserved. Game capture has no desktop fallback, avoiding a second display-capture source. Games must support the normal OBS game-capture hook; the profile does not bypass anti-cheat restrictions.

CQP fixes quantization, not perceptual quality. Lower QP normally retains more detail and increases file size and encoder work. This profile is a starting point to test, not a promise of lossless output or unchanged game FPS. The legacy QVBR mode remains available for comparison. Native AMD QP ranges are 1–51 for HEVC/H.264 and 1–63 for AV1; selecting AV1 cannot add AV1 encoding support to an RX 6600.

The **More detail / QP14** profile is an explicit experiment introduced in `1.0.1-rx.2`. It changes only the quantizer from the stable profile. Select it and Apply, then repeat the same camera movements and compare the original MP4 files, game FPS and actual replay duration. Higher packet volume can shorten the two-minute replay within the same memory budget. Select **Balanced / QP16** and Apply to return. Applying either profile rebuilds the encoder when its settings change, clearing the current replay; save any wanted clip first.

Version `1.0.1-rx.3` organizes the profiles as two selectable cards, followed by picture size, frame rate and format. Compression, encoder speed and replay memory are under **Advanced settings**. The checkmark describes the complete staged profile; custom changes can clear both checkmarks. The Status quality card shows the actual running encoder and compression, independently of unsaved edits. Replay timing guidance is available on the buffer card's tooltip.

Version `1.0.1-rx.4` reduces voice/status allocations, speeds up newest-file lookups and closes resource leaks on failed capture builds and settings-window replacement. See the [performance measurements and validation](performance-rx6600.md). Capture quality settings remain user-controlled.

## What changed

- AMD rate control and speed now reach the real encoder, independently of NVIDIA presets.
- CQP uses the native QP directly; legacy QVBR quality presets retain their existing scale.
- Nominal bitrate controls are hidden for AMD quality modes: OBS AMF does not apply those settings as bitrate ceilings in QVBR/CQP.
- Replay packet budgeting is independent of nominal bitrate. The budget is shared by regular/quick replay and limited to at most a quarter of available physical memory, with a 128 MiB floor.
- The live buffer timer is marked approximate. The saved toast probes the actual file duration.
- Engine status and logs expose the actual rate-control mode and QP.
- Kairos RX has its own settings folder, IPC names and startup entry. Its update source is this fork.
- A detected fullscreen game's process is retained across focus changes, preserving replay when Alt-Tabbing. The replay stops after the last retained game exits plus a 15-second grace period. A retained native process handle prevents PID reuse from keeping the wrong session alive.

Game detection remains heuristic: common browsers, players and shell apps are not retained, but an unlisted fullscreen application may be retained until its process closes. Protected processes that cannot be opened retain the previous foreground/grace behavior. This does not prove that OBS has hooked the game. Keep game capture selected without desktop fallback and check the saved picture.

The packet budget is not a hard process-RAM cap: libobs keeps at least two keyframe groups and temporarily retains packets while saving. High motion can fill the budget before 120 seconds, resulting in a shorter clip. Quality is not silently lowered to meet the budget. Additional RAM is used by capture, encoders, audio, libraries and the interface.

## Build and check

Requires a .NET 10 SDK and OBS Studio 32.2.2. From the repository root:

```powershell
.\tools\build-rx6600.ps1 -DotNet dotnet
dotnet run --project tests\Kairos.Tests -c Release -p:Platform=x64
.\dist\KairosRX\Kairos.exe --selftest-profile .\work\profile-smoke 12
.\dist\KairosRX\Kairos.exe --selftest-quality-trial .\reference-1080p60.mp4 .\work\trial16 16 25 58
.\dist\KairosRX\Kairos.exe --selftest-quality-trial .\reference-1080p60.mp4 .\work\trial14 14 25 58
```

The build helper requires a fresh output folder and never modifies the installed Kairos or OBS. The self-contained portable build needs no system-wide .NET install. Run `Kairos.exe` from its entire published folder, not by copying just that executable.

The headless profile check records the desktop using the real AMD profile, saves replay, probes dimensions/codec/timing and reports frame losses. It keeps clips and logs in its output folder. This validates plumbing and files, not visual equivalence to the uncompressed game.

The quality trial uses the same 1080p60 local file as its picture source, starting at the optional offset in seconds (58 in the example). Run the probes one at a time with other recorders closed. Each run saves media and JSON with the input hash, native encoder settings, frame counters and resource samples. Align corresponding frames before comparing image fidelity. An already-compressed input measures additional compression loss; it cannot establish fidelity to the original game. Software reference decoding affects CPU measurements, and these probes do not measure game FPS. A functional PASS does not imply zero dropped frames or a full two-minute replay.

For game validation, run only one recorder. Close the original Kairos before starting Kairos RX so they do not compete for the GPU or hotkeys. Use a practice area and repeat the same fast camera turns. Compare the original MP4 files at native resolution in the same player, checking moving edges/textures, encoder/render losses, actual clip duration, file size, and game FPS with capture on/off. Avoid exported or social-media copies for this comparison.

## Phase branches

1. `fix-motion-quality`: native AMD CQP and replay packet budget.
2. `feat-rx6600-profile`: explicit PC profile and isolated portable build.
3. `feat-amd-controls`: effective AMD controls, diagnostics and validation.
4. `fix-buffer-continuity`: retain the detected game session across focus changes.
5. `feat-qp14-trial`: reversible QP 14 comparison and same-source probe.
6. `refactor-capture-ui`: compact profiles, grouped advanced settings and actual capture details.
7. `perf-voice-allocations`: reuse voice resampling workspace while preserving samples.
8. `perf-status-polling`: update only changed visible status and guard asynchronous lifetimes.
9. `perf-library-lookups`: find newest files without constructing the full library.
10. `fix-window-lifecycle`: release closed-window subscriptions and idle work.
11. `fix-pipeline-cleanup`: release native resources after a failed capture build.
12. `perf-engine-overhead`: integrate phase 4 measurements and release version.

The branches are cumulative and integrated into `dev`. Further performance changes depend on real game comparison.

## Validation on this PC

- Release x64 build: no warnings or errors.
- General rx.4 suite: 606/607 passed, including all 17 new performance/lifetime regression checks. The sole failure is the same upstream 0.4 MB export-size case described below.
- UI revision: 26 focused profile, view-model and language checks pass, including whole-profile selection and actual versus unsaved compression readouts. Spanish, German and Arabic previews are checked at normal and minimum window sizes.
- New encoder, settings, profile, isolation and UI tests pass, including codec fallback and unknown persisted presets.
- General rx.2 suite: 587/588 passed, including all new profile and game-session tests. The sole failure, `ShareTranscodeTests.An_encoder_overshoot_is_retried_until_the_file_fits`, also fails on pristine upstream commit `04fd8bf`. It concerns fitting an exported clip into 0.4 MB, not recording or replay capture.
- A 12-second headless hardware run verified AMD HEVC CQP 16 / Balanced / analysis off at 1920×1080 and 60 FPS. Recording and replay files passed media checks; the run reported zero render and encoder frame losses. CPU averaged about 1.1% during this desktop check.
- The original Valorant clip was HEVC 1080p60 with about 4.4 Mbps average video bitrate. This is observational evidence, not a raw-reference quality measurement.
- The rx.2 same-source trials encoded 25 seconds of the same high-motion section with the same input hash, each with zero reported render or encoder losses. QP 16 produced a 147.97 MB recording; QP 14 produced 171.59 MB (15.97% larger). Both were HEVC 1920×1080 at 60 FPS.
- Eleven uniquely aligned 1080p frame pairs showed a modest reduction in additional compression loss: aggregate luminance PSNR 47.823 to 48.676 dB and block SSIM 0.993410 to 0.994189. This is a decoded compressed reference comparison, not a raw game reference or a perceptual percentage improvement. Peak sampled private memory was 471 / 491 MiB; software decoding makes these CPU/resource figures unsuitable as estimates of live capture overhead.
- Visual preference, full two-minute retention and FPS impact in live Valorant still require the same-scene game test. No lossless or zero-impact claim is made.
